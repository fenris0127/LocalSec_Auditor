# LocalSec Auditor v1.0 Scope

This document defines the v1.0 release-candidate boundary. The full-version
planning document remains the long-term roadmap; this file is the implementation
scope for v1.0.

## Included In v1.0

### Scanning

- Semgrep SAST scan tasks
- Gitleaks secret scan tasks
- Trivy filesystem vulnerability scan tasks
- Syft SBOM generation tasks
- Grype SBOM-based CVE scan tasks
- Lynis read-only Linux configuration scan tasks
- OpenSCAP read-only CCE/configuration scan tasks

### Orchestration

- Hermes task execution for supported scanners
- Task graph storage
- Dependency resolution
- Retry policy
- Progress API and UI
- Partial rerun
- Cancellation for pending/ready tasks
- Task logs with secret masking

### Findings And Analysis

- Unified findings storage for SAST, secret, CVE, CCE, and config findings
- Finding fingerprint support
- Ollama analysis through local `localsec-security`
- RAG reference retrieval for finding analysis
- LLM response evaluation before storing analysis output
- Hallucination and secret-leakage regression tests

### Reports And Exports

- Markdown report
- HTML report
- PDF export
- Findings CSV export
- Findings JSON export
- Executive summary
- RAG reference sections in reports
- CCE/config sections with verification and rollback guidance

### UI

- Dashboard summary
- Tools status and explicit Trivy/Grype DB update actions
- New Scan with Semgrep, Gitleaks, Trivy, Syft, Grype, Lynis, and OpenSCAP
- Scan detail with findings, CCE/config details, RAG references, progress, and
  scan comparison
- Report format selection for Markdown, HTML, PDF, CSV, and JSON

### Local And Offline Operation

- `LOCALSC_OFFLINE_MODE` support
- Update APIs blocked in offline mode
- Trivy and Grype DB update commands in update mode
- Semgrep local rules path support
- Local RAG document and vector-store flow

## Excluded From v1.0

- Security Chat
- Exception and approval workflow
- Bandit scanner integration
- Gosec scanner integration
- Checkov scanner integration
- Hadolint scanner integration
- Pull request or Git diff review
- Fine-tuning, QLoRA, or training pipeline code
- Automatic patching
- Automatic remediation
- Remote server modification features
- Automatic scheduled scanner database updates

## Required Local Dependencies

Install the tools required for the scan types you use:

- `semgrep`
- `gitleaks`
- `trivy`
- `syft`
- `grype`
- `lynis`
- `oscap` plus local SCAP content
- Ollama plus the local `localsec-security` model for LLM analysis

For offline use, scanner binaries, scanner databases, Semgrep rules, RAG
documents, embeddings, and the Ollama model must already be present locally.

## Security Principles

- Scanner output is the evidence source.
- LLM output explains scanner evidence; it is not a scanner result.
- RAG references are supporting context; they are not vulnerability evidence by
  themselves.
- Raw secrets must not be stored, printed, sent to the LLM, or emitted in
  reports/API responses.
- The system must not invent CVEs, CWEs, packages, or findings that are absent
  from scanner evidence.
- v1.0 must not modify production systems or apply automatic remediation.
